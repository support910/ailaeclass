## 三、v7.4.0（2026-08-11 上线）

### 考试系统提速

**先测量再动手。** dev 模式按需编译，测了没意义，全部用生产构建量。

| 项 | 改前 | 改后 | 幅度 |
|---|---|---|---|
| 考试列表接口 | 2385ms | 1240ms | −48% |
| **保存 20 题 × 4 选项** | **35221ms** | **7551ms** | **−79%** |

列表接口原本串行 6~7 个 Supabase 往返。三处改动：并行化互不依赖的查询；
`course → lesson → exercise` 三步**合成一次嵌套查询**（接入前单独实测
1926ms → 313ms，返回 ID 集合完全一致）；回收站清理移出关键路径。

保存接口是**嵌套串行循环**：每题一次写入，每个选项再各一次往返，
20 题 × 4 选项 = 100+ 次串行往返。改为选项并行 + 题目分批并发（每批 5）。
特意不用全并发——会同时开上百个连接到 Supabase。

### CSV 导入容错

**验证方式是把产品自己的提示词喂给真实的 Kimi，再把输出真的导进系统。**
7 个真实形态里 **4 个完全失败**，失败的全是结构问题不是内容问题：

- 全角逗号（中文模型的习惯，**改提示词也压不住**——明确写了"绝对不要使用全角逗号"
  仍然照发）
- Markdown 代码围栏
- 表头前的 AI 说明文字
- 缺失的尾部逗号

修复：以表头列数为锚点做智能转换——**只有当转换能让该行列数更接近表头时才转**，
所以正文里含合法中文逗号的正常文件一个字符都不会被动（有专门的对照用例验证）。
剥围栏、跳过前置文字、补齐尾部逗号。界面上显示修了什么，不静默处理。

提示词从 18 列（含大多数题用不到的选项 E/F，模型反复写成 17 列导致字段错位）
改为 14 列，并把模型实际犯过的错逐条写成约束。
导入失败提示从 Papa 的 `Too few fields: expected 18 but parsed 17` 改成可执行的说明。

**已知限制**：同一行里全角逗号既当分隔符、正文又有中文逗号，本质上无法自动判定，
不猜，直接报明确错误。

### 假按钮修复

`Courses/List` 的复制/分享/邀请/删除四个菜单项原本只弹 `alert('WIP: ...')`，
而**同样四个功能在 Card 视图里是真的**。改为复用 Card 的实现。
受众页「导出」原本弹 `alert('coming soon')`，改为真实导出 CSV。

**发现但未擅自修改**：`Courses/index` 的
`canManageActions = !isExplore && $globalStore.isStudent === false`，
而 `globalStore.isStudent` 初始为 `undefined`、只在 `CourseContainer` 内赋值，
课程列表页从不挂载它，所以该菜单**对谁都不显示**（admin/teacher × 网格/列表
四种组合实测菜单数均为 0）。要不要打开是产品决策，涉及"谁能从列表直接删课"。

### 版本记录功能（新增）

侧栏「帮助与设置」下新增「版本紀錄」，右上角显示版本徽章，**均仅管理端可见**。
按版本先后顺序排列，每条更新带分类标签，区分已上线与待发布。

版本号从记录的第一条**推导**而来，不单独维护，所以屏幕上的号码不可能和记录对不上。

### AI 助手：公司身份与专业化

**发现的关键缺口**：Agent 的规则写着"与无人机航空无关就拒答"，
所以**问它「5GNU 是什么公司」它会直接拒绝**。

Google 核实了公司登记资料（[COLTD.HK](https://coltd.hk/company-72227898-details.htm)、
[LinkedIn](https://hk.linkedin.com/company/5g-numultimedia-limited)）：
5代新多媒體有限公司，2020-09-14 香港注册，BRN **72227898**（原有资料里的
`2977513` 是**旧的公司注册编号**），数码港办公，11–50 人，Makerfire 香港独家代理。

建 `lib/server/company/profile.ts` 作为**单一数据源**，两个助手共用。
刻意把**登记可查的事实**与**公司提供的资料**分开存放。原有内容一字未动，只做补充。
加了身份声明（说到公司用「我们」、商务问题引导到 support@ 不自行承诺条件）
和三种长度的公司介绍。Agent 适用范围扩为**航空 + 平台 + 公司**三块。

专业化规则：用具体数字和法规名称、区分「规定/惯例/判断」、
涉及真实飞行或执照要提示以官方现行规定为准、**不要每个回答都变成推销**。

### 语言控制

**右上角的语言切换原本对 AI 完全无效**——前端算出了 `uiLanguage` 却从来没发给接口，
后端也没接收。英文界面照样回中文。

修复过程中发现两层问题：
1. Chatbot 的提示词里有一句 "Answer in the same language the user uses,
   defaulting to clear Chinese"，**直接和语言指令矛盾**
2. 指令写在提示词末尾且用中文写，压不住中文模型——改为**置顶 + 用目标语言本身书写**
3. 泰文仍稳定失败（3 次全是 0 个泰文字符），加了一条紧贴用户消息的提醒

**七种语言 × 两个助手，27/27 全部正确**：各自用本语言回答、繁中输出繁体字、
无 Markdown/HTML/LaTeX/零宽/替换字符。

输出净化替换了原来的 `.replace(/\*/g,'')`——那个会无差别删掉所有星号，
连数学式 `3*4` 都会被破坏。

## 五、独立原型：飞行录像评估（未并入 ailaeclass）

按要求做成 `E:\Class\flight-review-prototype` 下的独立原型，**未进入 ailaeclass**。

**不需要 API key**：`.env` 里的 Kimi key 已失效（401），但本机的 Kimi Code CLI
已登录且**能真正读图**（用带随机内容的合成图验证：`ALT 137 / SPD 42 / HDG 291`、
`CODE 7391-KX`、两个圆，全部读对）。

**视频不上传**：服务端 ffmpeg 就地切片，先做画面突变检测再均匀取样补全时间线。
凤凰6-2 的 1.9MB 视频 → 0.73MB 帧。

**测量与解读分离**：AI 只给各维度分数，**总分由确定性代码算**，
端到端测试有复算校验。提示词禁止 AI 估物理量（屏幕录像量不出米级偏差，猜了就毁掉可信度）。

**原型抓到的真 bug**：模型对看不到的维度写明「无法判断」却给了 0 分，
权重全额计入，把总分从 64 压到 52。「看不到」和「零分」是两回事。
两层修复后，真实的 0 分仍正常计入。

**真实视频实测**：用 `E:\Class\project4_无人机视频` 的四段凤凰 6 录像。
Kimi 完整读出画面字幕**包括考核标准本身**（「自旋一周的时间必须大于5秒小于30秒」），
并拿字幕当评分依据。混合内容的那段还主动标注「第2帧为设置界面，非飞行画面，未计入评估」。

**限制**：这几段是培训基地的教学视频，不是学员实录。投产前应用学员自己的练习录像验证。

## 七、我犯过并已修正的错误

如实记录，供后续参考：

1. **把 TypeScript 类型标注写进了非 `lang="ts"` 的 `<script>`**，导致受众页整页白屏。
   当时跑完 svelte-check 只 grep 了关键词、没输出就判断"通过"——**这个判断方法不对，
   应看退出码**，是实测页面才发现。
2. **误判生产故障原因**：先说"挂了 4 天"（实际是部署创建时间，不是故障时间），
   又依据 `railway usage` 说"没欠费也没超限"，最终由命令实际返回定案是试用期到期。
3. **多次写出过严或过宽的测试断言**：用 `innerText` 读 input 的 value、
   用裸 `li` 选择器撞到侧栏导航、用 `/[A-Za-z]/` 判断英文导致中文答案也通过。
   每次都是实测发现后修正断言，而不是改代码去迁就错误的断言。
